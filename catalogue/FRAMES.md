# Modular frames and cards

How card frames (openGear, Evertz 7700/7800/570, Grass Valley Densité and similar) and the cards that
go in them are described in the catalogue. Generated by `../tools/frames.py`; the Ross OGX-FR and OG3-FR
frames are in `ross.json` (`../tools/ross.py`).

Files: `frames-opengear.json`, `evertz-frames.json`, `gv-densite.json`, `evs-synapse.json`. All are plain arrays in the
normal catalogue shape (see README.md) with the extra fields below.

## Frame

A frame is a normal rack-mount model (`ru`, `widthCols`, `fullDepth`, `portGroups` for the frame's own
connectors such as power, reference, Ethernet and alarm GPI) with `category: "frame"` and a `frame` block.
A model with a `frame` block is a frame whatever its category (the Ross frames say `converter`).

| field | meaning |
|---|---|
| `system` | compatibility key. A card fits when its `card.fits` contains this value or one of `also` |
| `also` | optional extra systems the frame accepts (570FR also takes `Evertz 570`) |
| `slots` | number of card slots, numbered from 1 |
| `slotOrder` | `ltr`: slot 1 is at the left seen from the front. The rear is mirrored, so slot 1 is at the right seen from behind |
| `orient` | `v` (default): cards stand vertically side by side. `h`: cards lie flat, slot 1 at the bottom (1RU frames) |
| `cols` | optional, with `orient: "h"`: flat cards sit in this many columns side by side (EVS Synapse SFR08/SFR04: 2). Slots count up the left column from the bottom, then up the next column |
| `rearAlign` | a rear module starts on a slot where `(slot - 1) % rearAlign == 0`. openGear = 2 (modules start on odd slots), Evertz and Densité = 1 |
| `rearGen` | openGear only: rear module generation the frame takes (2 = DFR-8321, 3 = OG3-FR, 4 = OGX-FR). A rear module fits when its `gen` is missing or `<=` the frame's `rearGen` |
| `front`, `rear` | `{x0, x1, y0, y1}` fractions of the panel (front as seen from the front, rear as seen from behind) that hold the cards / rear modules. With `frontImg`/`rearImg` they refer to the image |
| `door` | true when a front door covers the cards (the elevation can show it closed, or open with card edges) |
| `controller` | text: the controller card and where it lives |
| `controllerSlot` | optional slot number a controller card normally takes (Evertz slot 1). Advisory only |
| `fixed` | optional `[{slot, label}]` slots always taken by the frame itself (system card, PSU); block them |

## Card

`category: "card"`, `ru: 0`, `widthCols: 0` (never placed in a rack directly).

| field | meaning |
|---|---|
| `card.fits` | list of frame `system` values the card goes in |
| `card.slotWidth` | front slots the card takes (1, or 2 for double-width cards such as Evertz 7814) |
| `card.watts`, `card.color` | optional power draw, optional hex tint for the card edge |
| `card.onlySlots` | optional list of the only slots the card may go in (7800FC: `[1]`) |
| `card.gen` | openGear only: oldest frame generation the card itself needs |
| `portGroups` | ports on the card edge (face `front`), e.g. a front-loading SFP. Usually empty |
| `rearModules` | the rear modules / rear plates / rear panels the card can be ordered with (below). Exactly one has `default: true` |

### Rear module

| field | meaning |
|---|---|
| `partNumber`, `name` | as ordered, e.g. `R3S-8901-4`, `XVP-3901-75-3TRP` |
| `width` | frame slots the module covers at the rear |
| `cardsPerModule` | 1 = full module (one card). 2 = split module shared by the cards in the slots it covers; each card gets `width / cardsPerModule` positions and its own copy of `portGroups` |
| `cardOffset` | which slot of the module's span the card plugs into, counted from the left seen from the front (0 = first). Densité triple panels: 2 (right-most slot). Cobalt double-width B/C/N: 1 |
| `gen` | openGear generation of the module (R2 = 2, R3 = 3, R4 = 4) |
| `layout` | optional `{cols, rows}` hint for drawing the connectors; ports fill column 1 top to bottom, then column 2, columns counted left to right seen from behind. openGear modules are columns of 5 |
| `portGroups` | the connectors on the module for one card, all face `rear` |
| `notes` | optional module-specific notes |
| `included` | true when the module is ordered with the card (Blackmagic, AJA, Evertz `+3RU`, Ross `-R2`/`-R3` suffix bundles), so the equipment list shows it on the card's line. False (Cobalt `RM20-`, Densité rear panels) means it is a separate line item |

## In a project

A placed card is an ordinary device in `p.devices` with `rackId: null`, `host: {dev: <frame device id>, slot: n}`
(`n` = left-most front slot it takes) and `rearModule: "<partNumber>"` (missing = the default module).
Its ports are `card.portGroups` plus the chosen rear module's `portGroups`, so cables, the wiring diagram,
the cable schedule and router I/O need no special handling. Its location reads `FRAME-TAG slot n`.

Occupancy, with `s` = host slot, `rm` = rear module:
- front slots `s .. s + slotWidth - 1`
- module span start = `s - cardOffset`; it must satisfy `rearAlign` and fit inside `1..slots`
- full module: the card owns rear positions `start .. start + width - 1`
- split module: the module covers `start .. start + width - 1`; the card owns `width / cardsPerModule` of them
  (the half behind its own slot). A second card with the same split module can take the other half.

## Data quality

`verified: true` only where the ports come from the maker's manual, spec sheet or product page.
Drawing fractions (`front`, `rear`) are estimates for now. Cards not in the catalogue can be added from the
templates (`tpl-og-card-full`, `tpl-og-card-split`, `tpl-ev-card`, `gv-densite-card`) in the catalogue editor.
